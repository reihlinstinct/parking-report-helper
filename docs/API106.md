# Jerusalem 106 API integration

The user supplied a client and states that the municipality granted API access.
This is an app login and shared subscription key, not a reporter-specific identity
credential. Allowed categories, rate limits, expiry and production/test scope are
not documented in the archive. Confirm those with the municipality before enabling
production. Category 1145 is taken from the supplied client, not independently verified.
No live request was made while developing this change.

## Private execution, public code

The reusable workflow runs in the CALLER's private repository, not in the public
repository. Never dispatch report data or secrets to public Actions. Pin both the
reusable workflow reference and `helper_sha` to the same reviewed full commit SHA.
Private pushes may invoke preview validation only. No public workflow handles data.
`api106.yml` rejects callers other than `reihlinstinct/parking-reports`.

The private repo keeps `addresses.json`, report folders and originals. The provided
address dataset is not bundled in public code; its provenance/licensing is unknown.
Reporter variables are `PARKING_REPORTER_FIRST_NAME`, `LAST_NAME`, `PHONE`,
`ID_NUMBER`, `EMAIL` (each has the full `PARKING_REPORTER_` prefix).
They must be private secrets/environment values, never command-line literals.
API secrets are `PARKING_106_SUBSCRIPTION_KEY`, `PARKING_106_USERNAME` and
`PARKING_106_PASSWORD`. Preview requires no API credentials.
No real names, ID numbers, phone numbers or keys are in examples or fixtures.

## Local offline preview

```
pip install ".[api]"
parking-report-106 /private/reports/REPORT_FOLDER --addresses /private/addresses.json
```

Preview validates one ready intake record, builds Hebrew report text, resolves its
municipal street code, converts coordinates to ITM and prepares a resized JPEG with
EXIF removed. It emits only the digest, photo byte count and offline status.
No network calls or state writes happen. Inspect the original private record and
photo locally to review all details; logs are not a review of the full report.

## Explicit local submission gate

Live execution is not enabled in the reusable workflow in this PR. Locally, it
requires `PARKING_106_ENABLE_LIVE=true`, `--submit` and `--approved-sha256` equal
to the reviewed preview digest. The digest binds reporter, payload and original
photo bytes. Gate approval does not itself prove identity or municipal permission.
Before any live execution review reporter, address, report text and photo together.
Live use of code 1145 requires the private record category `sidewalk_parking`;
other categories must wait for a verified municipal category mapping.
No secrets are printed. POSTs do not retry and redirects are refused.
Contact registration is a write, even before report creation.

## Durable ledger design for later live Actions enablement

Do NOT enable live Actions until these requirements are implemented and tested:

- The private workflow serializes all 106 jobs with a single concurrency group and
  `cancel-in-progress: false`; no other execution route may write the same ledger.
- Use a protected private environment for final approval and an explicit live flag.
  Approve one digest, not all records in a push. Submit only that frozen revision.
- Checkout the private ledger branch with write permission. Set
  `PARKING_STATE_GIT=1`, with `.106-state` unignored in the private repo. The runner
  commits and pushes every state transition before the next external effect.
- Reject stale checkouts; synchronize the ledger before selecting a report. Push
  failure blocks further work. Persist creating BEFORE CreateCase, created BEFORE
  attachment and complete AFTER confirmation. If a runner crashes after creation,
  the durable creating state blocks new creation until municipal reconciliation.
- A complete fingerprint returns the saved receipt without municipal requests.
  An uncertain creation is never retried. Failed attachments require checking the
  case first and explicit `--retry-photo`; attachment timeout can mean it succeeded.
- Altered inputs produce a different digest. Also keep a stable intake-record ID
  with the ledger to prevent edits from creating a second report for the same event.
  This stable-ID constraint is not implemented yet; do not run edited records live.
- Ledger/receipts never become public artifacts. Use a private branch excluded from
  report-push triggers to prevent state commits from triggering new submissions.

Local state uses an exclusive lock, atomic replacement, fsync, 0700 directories
and 0600 files. Without Git mode it protects one persistent local computer only;
GitHub cache/artifact storage is NOT a reliable pre-request transaction ledger.
No automatic uncertain-result reconciliation is claimed.

## Tests and Docker

Unit and functional tests use generated photos, synthetic reporter data and a mock
transport. Core/CLI tests remain; obsolete browser tests are removed. CI installs the API extra.
`docker build --target api` creates the optional non-root API image. Mount private
input read-only and a persistent private state folder read-write. Pass env values
using a private env file, not shell literals. No image contains credentials.
